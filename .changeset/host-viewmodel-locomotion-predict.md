Real 3D weapon view model, monster animation + locomotion, stop-oscillation prediction, visible tracers. HostDriver gains two optional hooks: `viewModel()` (camera-attached first-person gun: eye + forward*22 + right*8 - up*5, driver-owned model/skin handles, idle frame 0 vs muzzle-flash frame) and `entityFrame(id)` (per-entity MD2 frame; the renderer wraps out-of-range). The web driver implements both from the real pak tables (`v_weap` MD2s verified against pak0.pak: v_blast 56 / v_shotg 40 / v_machn 50 frames; soldier 475 / gunner 209): weapon skins tracked per class, frame from the move table `first` + offset. Monster bodies move via the new `monsterLocomotion` helper from @q2/game (called before `monsterThink` each tick, origin-space hull trace + gravity). The 2D gun silhouette is skipped whenever the 3D view model renders (death bars kept). Every frame the Host stages the owned cmd stream (since the newest snapshot, ending with the current cmd) so the local player uses friction-exact pmove replay instead of stale-velocity linear extrapolation — the stop-oscillation root cause. Player tracer beams now originate at the gun muzzle (off-axis): an eye-origin segment foreshortens to a single pixel by correct perspective, so it was effectively invisible head-on; muzzle-origin draws a visible streak to the impact. Tests: host smoothness + frozen-server pinning, devroom settle-monotonicity/no-overshoot, MD2-frame/locomotion render mapping, muzzle→impact bright-pixel streak, pak camera-attached gun + no-2D-double-draw.
