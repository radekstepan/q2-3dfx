Fix alias-model lighting at spawn (both barrels read identically): shade now samples the baked lightmap at each entity origin (straight-down trace with style scaling) plus dynamic-light falloff. Each backend follows its own original: software uses the ref_soft rule (Mod_LoadLighting brightest-component mono, ambient/shade clamps, colormap rows with brightness (255-4r)/128 measured against pics/colormap.pcx); WebGL uses the ref_gl rule (per-channel RGB sample, no clamps/inversion, gentle 0.7-2.0 directional factor from a procedural anormtab mirror, per-pixel dynamics unchanged). The naive mono+clamp mapping used first rendered everything ~2x too dark (near-black pickups/corpses), and the WebGL mono base saturated brights to fullbright. The spawn barrels now differ per position on both backends without crushing dark areas or blowing out brights.

Also plumbs RF_GLOW end to end (game SP_item sets it on every pre-placed pickup unless ITEM_NO_TOUCH; new optional Entity.glow + ExtraRenderable.glow, driver sets it, both renderers pulse ±0.1 at sin(time*7) floored at 0.8x): the under-stairs silencer visibly breathes instead of sitting black. Node-less worlds (devroom fallback) keep the legacy table so the pinned golden is untouched. Additive optional Entity field; frozen contracts otherwise unchanged (BRAIN.md §5 updated).

Enemy dynamic-light response + binary-dark sampling follow-up: the WebGL alias pass now transforms the dlight varying to world space (new uModel uniform; previously vWorldPos carried model-space verts compared against world-space lights, so muzzle/explosion flashes never visibly affected entities away from the origin). The software sampler skips luxel-invalid nearest hits in favour of farther lit faces (id RecursiveLightPoint `continue` semantics — previously a luxel-out-of-range face blacked out the whole entity) and solves luxels with the same affine triple convention as luxelWorldPositions (no vert-0 fan-triangulation misses on concave floors; id-faithful direct texinfo evaluation up to float error, +1e-4 luxel-boundary epsilon). In-flight blaster-bolt dlights are now pumped on all three production sites (dom tick, frameAsync, measureFrameStages), always after pumpMuzzleLight's per-frame expiry. Investigated but deliberately unchanged: Fibonacci-vs-anorms.h normal directions, (L.w-d)/L.w-vs-(I-d)/256 falloff scale, post-dot dynamic placement, grade-curve saturation, and style-RGB threading — all need golden review before tuning.

Dark-end lift (crawlspace-nook follow-up): walkable shadow is no longer pure black. Three parts: (1) production pak boots now install the C-exact shade rows from pics/colormap.pcx (new SoftwareRenderer.setShadeRowsFromColormapPcx; grade g maps to the physical row with matching measured brightness, so brights keep the validated no-blown look while dark rows regain id's authored faint structure instead of crushing every texel to palette black); (2) WORLD_GRADE_FLOOR=16 floors world light grades so unlit/dim luxels never resolve to palette black (bright and mid grades byte-identical; devroom's ~37 never reaches it, pinned golden 8f61c755 preserved); (3) the silencer crawlspace is pinned by a real-base1 render test (was 100% pure black, now dim but structured). Deliberately NOT changed: the world mono fold stays Rec.601 luma even though id folds by brightest channel (Mod_LoadLighting) — switching the shared path would re-pin the warm-tinted devroom golden; the floor carries the dark-end lift instead. Documented follow-up if the golden is ever re-pinned.
